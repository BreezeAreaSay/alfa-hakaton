## Минимальный сквозной кредитный путь (стр. 13–15)

| Элемент пути | Как выполнено |
|---|---|
| Потребность → выбор продукта → заявка с суммой, сроком, целью и сведениями о клиенте | Подбор по цели или описанию, расчёт для подходящих продуктов, заявка с данными компании из ЕГРЮЛ/ЕГРИП |
| Приём, проверка полноты и корректности, приведение к единой форме, уточнение | Шаг «Проверка данных», признаки для скоринга из всех источников, статус «Нужна информация» с перечнем и сроком |
| Обогащение из внешних источников: БКИ, ЕГРЮЛ/ЕГРИП, ФНС «Прозрачный бизнес» | Шаги конвейера к симулятору этих систем, а также ГИР БО и данным банка; повторы, ожидание и circuit breaker при сбоях |
| Скоринг отдельно от кредитного решения | Балльная карта из 9 факторов → класс риска; решение учитывает продукт, сумму, срок, стоп-факторы, флаги и лимит. Один класс риска даёт разные условия для разных продуктов |
| Небинарный итог: изменить сумму или срок, предложить другой продукт, запросить информацию | Автоматические контрпредложения (больше срок или меньше сумма), решение аналитика с выбором другого продукта и пересчётом условий, запрос информации |
| Оформление документов и предоставление финансирования | Договор и график в PDF, простая электронная подпись в кабинете, выдача через симулятор АБС, кредит и график платежей у клиента |

## Критерии успеха (стр. 9)

| Критерий | Чем подтверждается |
|---|---|
| Целостность решения | Сквозной путь от потребности до выдачи; 17 сценариев через API, 10 в браузере и Postman-коллекция проходят автоматически |
| Готовность к проверке | Запуск одной командой, тестовые учётные записи с быстрым входом, сброс данных, пошаговые сценарии |
| Качество пользовательского опыта | Подбор по задаче, расчёт до заявки, автозаполнение, статус в реальном времени, объяснение решений, интерфейс на дизайн-системе Альфа-Банка ([design.md](design.md)) |
| Согласованность модулей | Одна машина состояний, данные заявки используются на всех этапах, переходы проверяются централизованно |
| Enterprise-ориентированность | Транзакционная очередь заданий, идемпотентность, оптимистическая блокировка, повторы и circuit breaker, ролевой доступ, журнал действий, JSON-логи, миграции, CI ([architecture.md](architecture.md)) |
| Потенциал развития | Путь к боевому контуру и план развития ([architecture.md](architecture.md#масштабирование-и-путь-к-боевому-контуру), [product.md](product.md#развитие)) |

## Ограничения (стр. 10–11)

| Ограничение | Как соблюдено |
|---|---|
| Комплексность | Клиентский путь, кредитная логика и инженерные практики в одном решении |
| Независимость от платных ресурсов | Только свободные компоненты, без платных API, подписок и покупных данных ([THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES)) |
| Синтетические данные | Все данные созданы командой |
| Автономность | Доступ к системам банка не нужен; внешние проверки — в симуляторе |
| Сценарий внутри продукта | Уведомления, чат, документы, подписание и выдача — только в кабинете; email, SMS, мессенджеры и звонки не используются |
| Допустимые упрощения описаны | Раздел «Упрощения» в [process.md](process.md#упрощения) |
| Веб-интерфейс, не мобильное приложение | Веб-приложение для браузера |
| LLM только с открытыми весами | Qwen3 4B в Ollama или другой бесплатный сервис с открытыми весами; ИИ по умолчанию выключен ([ai.md](ai.md)) |
